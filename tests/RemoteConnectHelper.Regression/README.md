# 远程连接助手缺陷回归

依赖 Windows 10/11、.NET 10 SDK，与主项目使用同一 Windows 框架。无额外测试框架依赖。

默认运行只调用本地测试回调，不启动向日葵或 ToDesk、不读取或修改剪贴板、不发起远程连接。

```powershell
& 'E:\开发工具\dotnet\dotnet.exe' run --project tests/RemoteConnectHelper.Regression
```

覆盖截图缓存身份、回车/Esc 多次使用及长按、倒计时、连接中关闭和重识别、异常后重试、设备码校验、取消后禁止输入。

还覆盖密码弱线索/隐藏值的核对提示、ToDesk 安全密码大小写，以及低清拍照的实际 OCR。增强识别保持原图坐标与原图内容；设备码误读为含字母的串时也不能再次被选成密码。

真实反馈截图及预期远程码/密码不发布到公开仓库。拥有本机样本时，可参照 `testcases/private-fixtures.example.json` 创建被忽略的 `testcases/private-fixtures.json`，其中 `Purpose=ocr` 用于原图 OCR 回归，`Purpose=preview` 用于可选界面检查。未配置私有样本时，该组明确显示 SKIP，不计为通过；其他模拟数据测试照常运行。设置 `RCH_TEST_DISABLE_LOCAL_FIXTURES=1` 可以在本机验证公开仓库缺少私有样本时的路径。

2026-10-14 直连规则：软件已确定且设备码有效，就自动连接；图像增强、密码待核对和空密码不再单独要求点击确认。只有软件不明确、设备码缺失/无效或识别错误时才停留手动处理。新增策略矩阵及确认卡加载后实际进入连接回调的回归，回调只返回本地测试结果，不启动远程软件。既有“截图后自动连接”配置仍决定是否无需点击悬浮球/热键即触发整条识别流程。

默认测试还检查远离设备码区域的像素不会被预览裁剪、手动编辑框保持可用。它不证明真实鼠标点击和实际键盘输入通过；这些由用户手测。本次窗口改动没有自动操作桌面做真机输入验收。

界面和模拟输入验收使用 `--ui <截图输出目录>`：在本机显示受控的两个输入框，通过向日葵实际共用的填码方法验证旧密码替换、免密清空和慢速重填；随后运行真实 WPF 确认卡，检查八秒无人操作关闭、停止连接和取消提示，并截取显示画面。这些连接仍使用测试回调。运行时会短暂移动鼠标并在本地测试输入框打字。

```powershell
& 'E:\开发工具\dotnet\dotnet.exe' run --project tests/RemoteConnectHelper.Regression -- --ui 'E:\开发产物\RemoteConnectHelper\回归截图'
```

通过时退出码为 0，任何检查失败时为 1。真实远程软件的窗口定位、网络连接和断开实际客户会话仍需独立上线验收。
